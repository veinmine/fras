# Building FRAS

FRAS is a native [Horizon](https://github.com/horizon-rust/horizon) mod, packaged as one `.hmod`. It uses
the mod API's hooks only: **no mixins** so far. `[native]` in `horizon-mod.toml` pins the Horizon build
(`f1bb66f`, Nightly of 22 Nov 2026) and the horizon-mixins commit; it stays so the launcher builds the mod
natively and so a mixin can be added where no hook exists. Any mixin added later must be listed here with
the reason.

```sh
cargo horizon-mod check                                  # fetches the SDK into .horizon/sdk/ (once)
cargo test                                               # the physics and the game-free logic
cargo clippy --all-targets -- -D warnings
horizon-launcher native-build . --trust-native-code      # build it into the selected instance
cargo horizon-mod build                                  # the package: target/horizon-mod/fras.hmod
```

CI (`.github/workflows/ci.yml`) runs `cargo fmt --check`, clippy with `-D warnings` and the tests against
the pinned SDK. The Horizon watch is described in [watch.md](watch.md).

## Layout

- `src/sim/`: the physics, free of the game, with the unit tests.
  - `geom.rs`: positions, axes, directions.
  - `rot/`: the rotational network (spec `specs/rotational-network.md`): `part.rs` (the parts and their
    numbers), `net.rs` (membership, components, rebuilds), `solve.rs` (the per-tick solve), `damage.rs`
    (warnings, jams, repair).
  - `grind.rs`: the grinder (spec `specs/grinder.md`).
- `src/game/`: the game layer. Block hooks only queue work; `server::level_tick` (from `level_tick_post`)
  reads queued parts into the network, applies cranks, water wheels and grinder loads, ticks the network,
  then plays effects and syncs the block entities.
  - `parts.rs`: block and block-entity hooks; `tools.rs`: wrench, belt, tooltips; `grinder.rs`: the
    grinder's container, recipes and screen; `world.rs`: bearing mounts, clutches, large pulleys, water
    wheels; `draw.rs`: the rotating parts on the client; `effects.rs`: sounds and particles.
- `data/fras/` and `assets/fras/`: generated by `tools/gen_content.py` (block and item declarations,
  blockstates, models, loot, tags, recipes, creative tab) and `tools/gen_textures.py` (the placeholder
  item textures, own work). Run both from the repository root after changing them; the language files are
  hand-written.

## Where 0.1 differs from the spec

Tuned in a game so the exit criteria hold; reported to veinmine:

| Spec | 0.1 | Why |
| --- | --- | --- |
| Spin-up ~2 s, coast ~3 s | `ACCEL` = 40: spin-up ~1 s, coast ~4 s | One constant sets both (a first-order lag), so the two targets can't both be met; 40 keeps the crank responsive and lets a line coast visibly. |
| Viscous friction as written | Quartered, `CONST_FRICTION` raised to 0.15 | With the spec's numbers a water wheel geared up 4× stalled well below the 64 RPM of exit criterion 3; now ~73 RPM at the bevel. |
| A rebuild of 2000 parts in 2 ms | ~6 ms (release build, measured in a test) | Rebuilds happen only when the network changes, not every tick. |

Not in 0.1 (no hook yet, or left for later):

- The grinder's container is the same for every side (`ModContainer` is static per block), so it can't
  refuse items without a recipe or insertion through the socket side.
- Items tossed onto the grinder aren't pulled in.
- The hand hammer is a crafting remainder and doesn't wear out.
- Shift-click in the grinder screen uses the default quick-move.

## Testing in a game

Use a separate instance (`fras-dev`). Speed things up: `/tp` to the test site instead of walking, and
`/tick rate 100` (or `/tick sprint`) while waiting for spin-up, coasting, warnings or grinding. The exit
criteria are in section 13 of `specs/rotational-network.md`.
