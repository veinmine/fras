# Building FRAS

FRAS is a native [Horizon](https://github.com/horizon-rust/horizon) mod, packaged as one `.hmod`. It uses
the mod API's hooks only: **no mixins** so far. `[native]` in `horizon-mod.toml` pins the Horizon build
(`f1bb66f`, Nightly of 22 Nov 2026) and the horizon-mixins commit; it stays so the launcher builds the mod
natively and so a mixin can be added where no hook exists. Any mixin added later must be listed here with
the reason.

```sh
cargo horizon-mod check                                  # fetches the SDK into .horizon/sdk/ (once)
cargo test                                               # the physics and the game-free logic
cargo clippy --all-targets -- -D warnings
horizon-launcher native-build . --trust-native-code      # build it into the selected instance
cargo horizon-mod build                                  # the package: target/horizon-mod/fras.hmod
```

CI (`.github/workflows/ci.yml`) runs `cargo fmt --check`, clippy with `-D warnings` and the tests against
the pinned SDK. The Horizon watch is described in [watch.md](watch.md).

## Layout

- `src/sim/`: the physics, free of the game, with the unit tests.
  - `geom.rs`: positions, axes, directions.
  - `rot/`: the rotational network (spec `specs/rotational-network.md`): `part.rs` (the parts and their
    numbers), `net.rs` (membership, components, rebuilds), `solve.rs` (the per-tick solve), `damage.rs`
    (warnings, jams, repair).
  - `grind.rs`: the grinder (spec `specs/grinder.md`).
  - `multi/`, `steam/`, `fluid/`, `plant/`: 0.2's boilers and tanks (cuboid rule, formation), the thermal
    model, fuels and failures, pipes, valves and pumps, and the plant that ties them together and steps
    every 4 ticks (specs `multiblocks.md`, `steam-and-heat.md`, `fluids-and-pipes.md`).
- `src/game/`: the game layer. Block hooks only queue work; `server::level_tick` (from `level_tick_post`)
  reads queued parts into the network, applies cranks, water wheels and grinder loads, ticks the network,
  then plays effects and syncs the block entities.
  - `parts.rs`: block and block-entity hooks; `tools.rs`: wrench, belt, tooltips; `grinder.rs`: the
    grinder's container, recipes and screen; `world.rs`: bearing mounts, clutches, large pulleys, water
    wheels; `draw.rs`: the rotating parts on the client; `effects.rs`: sounds and particles.
  - 0.2: `steam.rs` (the plant in a level: queued parts, the step, formations, bursts, explosions,
    scalding, warnings), `pipes.rs` (connections, valves and buckets by hand), `firebox.rs`,
    `steam_inspect.rs` (the wrench's lines), `steam_draw.rs` (flywheel, rod, handwheel, gauges) and
    `shell_model.rs` (the `fras:shell` model loader that draws formed boilers and tanks as one rounded
    shell).
- `data/fras/` and `assets/fras/`: generated by `tools/gen_content.py` (block and item declarations,
  blockstates, models, loot, tags, recipes, creative tab) and `tools/gen_textures.py` (the placeholder
  item textures, own work). Run both from the repository root after changing them; the language files are
  hand-written.

## Where 0.1 differs from the spec

Tuned in a game so the exit criteria hold; reported to veinmine:

| Spec | 0.1 | Why |
| --- | --- | --- |
| Spin-up ~2 s, coast ~3 s | `ACCEL` = 40: spin-up ~1 s, coast ~4 s | One constant sets both (a first-order lag), so the two targets can't both be met; 40 keeps the crank responsive and lets a line coast visibly. |
| Viscous friction as written | Quartered, `CONST_FRICTION` raised to 0.15 | With the spec's numbers a water wheel geared up 4× stalled well below the 64 RPM of exit criterion 3; in the sim test now ~73 RPM at the bevel. |
| Wooden bevel gear max 64 RPM | 56 RPM | In game, with more parts on the line than the sim test, a 32 Nm wheel through two gearboxes levelled off at 63.9 RPM, just under 64, and never jammed. 56 makes it jam; a crank through two gearboxes (~61 RPM) now overspeeds wood too. |
| Water wheel 4 Nm per flowing block | 8 Nm per block, still capped at 32 Nm | Tested in game: a clean overshot side gives 4 blocks' worth and the far side's flow pushes the other way, so 4 Nm per block topped out at 16 to 24 Nm and a wheel couldn't run one grinder well (criterion 2) or overspeed a wooden bevel through two gearboxes (criterion 3). With 8 a clean overshot side reaches the 32 Nm cap the spec's balance assumes. Open water spilling over the hub cancels the push: wall the source in. |
| A rebuild of 2000 parts in 2 ms | ~4 to 6 ms (release build, measured in a test); a steady tick costs ~3 µs, well under the 0.1 ms target | Rebuilds happen only when the network changes, not every tick. |

Not in 0.1 (no hook yet, or left for later):

- The grinder's menu (`fras:grinder`) takes only grindable items into its input and nothing into its outputs,
  but hoppers follow the container's faces, which are the same for every side (`ModContainer` is static per
  block): a hopper can put any item into the input, through the socket side too.
- Items tossed onto the grinder aren't pulled in.
- The hand hammer is a crafting remainder and doesn't wear out.
- Shift-click in the grinder screen uses the default quick-move (first slot with room, never a result slot).

## Where 0.2 differs from the spec

| Spec | 0.2 | Why |
| --- | --- | --- |
| Flywheel and pump friction 0.05 | 0.0125 | 0.1's quartered convention for viscous friction (see above), so the same number means the same drag. |
| Flywheel inertia 200 | 90 | With 200 an engine at 4 bar took 22.5 s to spin up against the ~10 s of exit criterion 2 (sim test). |
| 64 flag combinations × 3 axes of static shell models | One model file per combination naming the `fras:shell` loader, which builds the quads | Generated JSON can't round edges without many small elements; the loader draws only outer faces with rounded long edges, every UV inside its sprite. |
| Firebox: extraction from below takes the empty buckets lava leaves | No extraction | A `ModContainer`'s output faces are static; the empty bucket stays in the slot for the player. |
| Gauges and sight glasses don't tick | They tick, like the tachometer | The block entity reads the plant and syncs only when the shown value moves. |
| Pump waterlogging | Not yet | |
| Fluid capability for other mods | Not yet | Left for 0.3 (fluids spec 10). |
| Explosion setting reaches dedicated servers | Client setting; a dedicated server stays on "full" | Settings are client-side in this Horizon build. |
| Pump rocking beam moves with speed | Static | |
| A new pipe connects the face it was placed against first | Faces in direction order | Contents still decide which faces join. |
| Flywheel blocked: "Blocked by Stone at …" | "Blocked at x y z" | No block names from a state in the API. |
| Performance: 50 boilers, 50 engines, 2000 pipes under 0.2 ms per tick; a 2000-pipe rebuild under 2 ms | ~0.46 ms per tick in game (steam step 0.12, shell saves 0.13, block entities 0.20, of which ~0.13 is Horizon copying each block entity's data); rebuild ~0.6 ms alone, ~2.1 ms with the 50-boiler plant in the level | Measured on archmage. A rebuild rebuilds every plant in the level; per-network rebuilds and fewer ticking block entities are left for later. |
| Hot steam pipe 1 damage per second | 1 damage every half second, like a magma block | At 1 per second a fed player's regeneration cancelled it out in game. |

## Testing in a game

Use a separate instance (`fras-dev`). Speed things up: `/tp` to the test site instead of walking, and
`/tick rate 100` (or `/tick sprint`) while waiting for spin-up, coasting, warnings or grinding. The exit
criteria are in section 13 of `specs/rotational-network.md`.
