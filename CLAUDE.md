# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

FRAS (Fire, Rust and Steam, mod id `fras`) is a native [Horizon](https://github.com/horizon-rust/horizon)
technology mod for Minecraft 26.3, written in Rust: shaft power (0.1), steam (0.2), regulation and rust
(0.3), and the factory milestone 0.4 (belts, elevators, line machines). `develop` is the working branch:
base work on it and target pull requests at it.

## Commands

```sh
cargo horizon-mod check                              # fetches the pinned SDK into .horizon/sdk/ (needed before anything else)
cargo test                                           # sim physics, game-free logic, recipe tree, translation keys
cargo test <name>                                    # one test or module, e.g. `cargo test sim::rot` or `cargo test every_tier_one_item_is_craftable`
cargo fmt --check
cargo clippy --all-targets -- -D warnings
horizon-launcher native-build . --trust-native-code  # build into the selected game instance (on archmage)
cargo horizon-mod build                              # package: target/horizon-mod/fras.hmod
python3 tools/gen_content.py                         # regenerate data/fras and assets/fras JSON
python3 tools/gen_textures.py                        # regenerate placeholder item textures
python3 tools/vanilla_recipes.py                     # refresh vanilla recipes for the clash test (after a game update)
```

`Cargo.toml` depends on `horizon-mod-api` by path into `.horizon/sdk/` (gitignored), so nothing compiles
until the SDK is fetched. While GitHub has the horizon-rust org flagged, prefix SDK fetches with
`HORIZON_SDK_BASE=https://horizon-mirror.nikitagrimm.de` (CI sets the same at the top of `ci.yml`).
CI runs fmt, clippy with `-D warnings` and the tests, so all three must pass.

## Architecture

- **`src/sim/`**: the rules, with no Horizon types at all, and nearly all unit tests. `rot/` is the
  rotational network (parts, membership/rebuilds, per-tick solve, damage); `multi/`, `steam/`, `fluid/`
  and `plant/` are boilers and tanks, the thermal model, pipes, valves and pumps, tied together in
  `plant/` which steps every 4 ticks; `belt.rs` and `machine/` are 0.4's belt lines and machines;
  `grind.rs`, `rust.rs`, `geom.rs` the rest. New mechanics go here first, tested without the game.
- **`src/game/`**: a thin layer that puts `sim` on Horizon through the mod API's hooks and parts only.
  **No mixins**: any mixin added must be listed with its reason in `docs/development.md`. Block hooks
  (`parts.rs`) only queue work; `server::level_tick` (from `level_tick_post`) drains the queues into the
  per-dimension sim state, applies inputs (cranks, wheels, loads), steps the network, plant and belts,
  then plays effects and syncs block entities. Client drawing is in `draw.rs`, `steam_draw.rs`,
  `belt_draw.rs` and the `fras:shell` model loader (`shell_model.rs`).
- **`src/lib.rs`**: registration. `game::blocks::Block::ALL` is the block list; `ITEMS` and `PAINTED`
  (rusting blocks that get a `painted_<name>` item) are here too.
- **Content**: `data/fras/` and `assets/fras/` are mostly generated by `tools/gen_content.py` (declarations,
  blockstates, models, loot, tags, recipes, creative tab). Edit the script and rerun it, not the JSON.
  Language files (`en_us.json`, `pl_pl.json`), grinding recipes and textures are hand-written.
- **Translations**: English and Polish. `cargo test` fails if a language lacks a key English has or the code
  uses a `fras.` key no language has. Polish terms follow `docs/translations/dictionary.md` (vanilla's
  official names where they exist).

## Specs and docs

The design is `Fire, rust and steam - design.md`; `specs/*.md` are the specs the code follows, and code
comments cite them by section (e.g. "spec 8.2"). Where an implementation deliberately departs from a spec
(tuning in game, an API limit), record it in the "Where 0.x differs from the spec" table in
`docs/development.md` with the reason. Player-facing docs: `README.md` (block tables per milestone),
`docs/rotational-network.md`, `docs/grinder.md`, `docs/factory.md`, `docs/progression.md`.
`docs/watch.md` lists API gaps FRAS waits on (tracked by the weekly Horizon watch workflow and
`.github/horizon-watchlist.txt`). `spike/` holds only the milestone 0 findings; a second crate inside the
repo makes the package invalid.

## Testing in a game

Done on archmage with the Horizon launcher, in a separate instance (`fras-dev`); start the client with
`offscreen` when its window isn't visible. Speed things up: `/tp` instead of walking, `/tick rate 100` or
`/tick sprint` while waiting. `/fras` debug commands (`docs/debugging.md`) dump part/network/line/machine
state as JSON to `fras-debug/<name>.json`, log events, measure perf and build rigs
(`/fras scenario ore_line`, `test_engine`). Exit criteria per milestone: section 13 of
`specs/rotational-network.md` (0.1), 11 of `specs/regulation.md` (0.3), 9 of `specs/progression.md` (0.4).
For rust: `/gamerule random_tick_speed 300` and rain. Feed test boilers from a big tank
(`fill … fras:storage_tank{pv:1,water:4000d,content:"water"}`) or they run dry and burst.
